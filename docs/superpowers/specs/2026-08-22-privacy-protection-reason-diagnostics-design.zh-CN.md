# 隐私保护原因与诊断设计

## 摘要

OpenChronicle 将解释每块显示器为什么处于已保护、已暂停或失败状态。截图选择、AX gate、
原生浮层和新的应用内诊断页都使用同一份权威保护快照。

三个独立设置分别控制原因显示位置、详细程度和浮层展开方式。最终确认的默认值是：浮层与
诊断页同时显示、具体值、鼠标悬停展开。

## 目标

- 每个可见隐私标识都能解释真正控制捕获的原因。
- 支持仅浮层、仅诊断页、浮层加诊断页三种显示方式。
- 支持仅固定类别、具体值、分层显示三种详细程度。
- 支持常显、悬停和点击三种浮层展开方式。
- 具体应用名、bundle ID、窗口标题和规则内容不得进入捕获历史、日志、memory 或模型请求。
- 诊断页显示具体值时只保护诊断窗口所在屏幕；`separate` 模式下其他屏幕继续捕获。
- 保持现有 fail-closed、浮层样式和多屏语义。

## 非目标

- 不读取后台 AX Tree、网页内容或像素来发现新的敏感信息。
- 不新增远程诊断、MCP 诊断工具或 TCP/HTTP 接口。
- 不保存具体原因历史。
- 不在截图中对单个窗口区域做像素遮盖；保护仍以整块显示器为单位。
- 不改变 denylist 规则的匹配语义。

## 配置

`[capture]` 新增三个设置：

```toml
privacy_reason_display = "hybrid"
privacy_reason_detail = "exact"
privacy_reason_trigger = "hover"
```

### 显示位置

| 值 | 行为 |
|---|---|
| `overlay` | 原因只显示在原生浮层。 |
| `diagnostics` | 原因只显示在应用诊断页。 |
| `hybrid` | 浮层和诊断页都显示，默认值。 |

只要 `privacy_indicator_style != "off"`，现有状态标识仍然可见。显示位置只控制附加原因。
样式为 `off` 时不显示浮层原因，但诊断页仍可使用。

### 详细程度

| 值 | 行为 |
|---|---|
| `category` | 只显示“应用规则、标题规则、手动暂停”等固定类别。 |
| `exact` | 显示可用的应用名、bundle ID、窗口标题和命中规则，默认值。 |
| `tiered` | 先显示固定类别；诊断页需要主动操作才显示具体值，浮层始终只显示类别。 |

具体值进入 UI 前会移除控制字符并限制长度。原始异常文本和 AX 内容永远不是原因详情。

### 浮层展开方式

| 值 | 行为 |
|---|---|
| `always` | 原因始终展开。 |
| `hover` | 鼠标进入标识范围时展开，移出后收起；默认值。 |
| `click` | 单击小标识区域切换展开；该次点击不会传给底层应用。 |

`hover` 模式下浮层继续完全鼠标穿透。helper 只观察全局鼠标位置，不获取焦点，也不接收
底层点击。`click` 模式只有小标识命中区域接收鼠标，屏幕其他位置仍完全穿透。浮层始终是
非激活窗口，不能成为 key/main window。

## 用户可见原因

### 已保护

- 应用名命中规则；
- bundle ID 命中规则；
- 窗口标题命中规则；
- 存在标题规则但无法确认可见标题，因此保守保护该屏幕；
- `all` 模式被另一块屏幕的命中连带保护；
- 诊断页正在显示具体值，因此保护诊断窗口所在屏幕。

### 已暂停

- 无限期手动暂停；
- 定时暂停，包括有效恢复时间；
- 定时暂停仍在等待警告/心跳安全条件。

### 截图已停用

- 暂停状态不可读；
- 窗口 helper 不可用、退出或输出格式错误；
- 显示器 inventory 为空或非法；
- 返回了多个活动窗口；
- 活动窗口或敏感窗口无法映射到显示器；
- 必需的浮层确认未成功。

一块屏幕有多个原因时，浮层显示最高优先级原因和 `+N`；诊断页列出全部原因。优先级依次
为：失败、暂停、诊断页自保护、直接规则命中、未知标题保守保护、`all` 连带保护。

## 权威原因模型

`ProtectionSnapshot` 新增不可变的每屏原因记录。每条记录包含：

- 固定 `ProtectionReasonCode`；
- 目标显示器 ID 和可选来源显示器 ID；
- 状态与优先级；
- 命中字段类型；
- 是否为连带保护；
- 可选具体值：检测 inventory 已经读取的应用名、bundle ID、窗口标题和命中规则。

规则匹配改为返回结构化记录，不再在屏幕映射后丢弃 app/bundle/title 匹配原因。不会增加
AX Tree 遍历或截图分析。截图 gate、AX gate、浮层命令、日志和诊断页都读取同一快照。

诊断页自保护原因会和当前隐私决策组合，不会覆盖 denylist、暂停或失败原因。

## 浮层数据流

daemon 继续通过现有 stdin/stdout 本地协议控制 `mac-privacy-overlay`：

- `category` 只发送固定原因码和数量；
- `exact` 只向当前快照已经排除的显示器发送有限长度的具体字段；
- `tiered` 向浮层发送固定类别；
- helper 不记录命令内容；
- 原因 UI 渲染失败时退回固定类别，不改变捕获保护。

收起状态仍是现有的已保护、已暂停或失败标识，触发方式只改变原因内容是否展开。只有浮层
可见时才以有限频率检查鼠标位置；悬停不需要全局 event tap。

## 应用诊断页数据流

daemon 在 `~/.openchronicle/runtime/privacy-diagnostics.sock` 提供专用 Unix Socket。runtime
目录只允许当前用户访问，socket 只接受同一用户。它不是 MCP，也不监听网络端口。

socket 向原生应用推送带 generation 的诊断快照。固定类别可以直接读取；具体值必须先获得
诊断页所在显示器的保护租约：

1. 诊断页确认自己的窗口位于哪块显示器；
2. 请求在该显示器显示具体值；
3. daemon 为该显示器添加诊断自保护原因并发布新 generation；
4. 应用等待浮层与捕获策略确认该 generation；
5. daemon 才返回具体值，应用才解除遮盖。

保护 guard 只保存非敏感元数据：租约 nonce、应用 PID 和受保护显示器 ID。具体原因值不
落盘。daemon 重启时可先读取 guard，在具体诊断窗口可能仍存在时保持 fail closed。

窗口移动时，应用先遮盖具体值；daemon 先保护新显示器，再释放旧显示器，确认后重新显示。
离开页面时先隐藏具体值，再释放租约。已有手动或定时暂停完全独立，不会被诊断页释放。

应用连接失败或状态不确定时隐藏具体值并保持租约。只有确认应用进程已经退出后才能自动
移除租约。`all` 模式下，只要诊断页所在显示器受保护，现有语义仍会省略整张虚拟桌面截图。

## 原生应用

Capture 设置页新增三个紧凑选择器：原因显示位置、详细程度、浮层展开方式。显示位置为
`diagnostics` 或浮层样式为 `off` 时，浮层展开设置禁用。

新增 **Protection Diagnostics** 页面，每块显示器显示一行：

- 显示器标签和主显示器状态；
- inactive、protected、paused 或 failed；
- 当前详细模式允许的全部原因；
- 截图和活动窗口 AX 当前是否被阻止；
- snapshot generation、浮层确认状态和更新时间。

`exact` 模式下，页面显示具体值前自动获得本屏保护租约；`tiered` 模式先显示类别，并提供
主动显示具体值的操作。

## 日志和隐私边界

状态变化日志可以包含 generation、显示器 ID、固定原因码、模式和确认状态，但不得包含
具体应用名、bundle ID、窗口标题、规则文本、socket payload、租约 nonce 或原始异常文本。

具体原因不得复制到 capture JSON、OpenChronicle 保存的截图、FTS、timeline、session、
memory Markdown、模型 prompt、模型失败事件或 MCP 返回。它们只存在于 daemon 快照、本地浮层
命令和已受保护的诊断 UI 中。

这可以防止 OpenChronicle 捕获自己的具体诊断内容，但无法阻止其他录屏或屏幕共享软件看到
用户主动显示在屏幕上的值。

## 失败处理

- socket 不可用：诊断页只显示安全的不可用状态，具体字段保持遮盖；
- 租约确认超时：具体字段保持遮盖，目标显示器继续受保护，直到能够确认安全释放；
- 应用崩溃或断连：应用进程可能存在时保持租约；确认进程退出后才清除；
- daemon 重启：开始捕获前加载非敏感 guard，并要求应用重新握手后才能显示具体值；
- 浮层 helper 失败：保持现有 capture fail-closed；原因 UI 失败不能削弱截图或 AX gate；
- 鼠标跟踪失败：收起原因内容，保留状态和捕获决策；
- 配置值非法：归一化为 `hybrid`、`exact`、`hover`。

## 性能

- 复用现有顶层窗口 metadata 和 denylist 检查，不新增后台 AX Tree 遍历；
- 在现有 snapshot 构建过程中生成原因记录；
- 只有 generation 变化时才推送诊断；
- 只有浮层可见时才以有限频率检查鼠标位置；
- 所有 IPC payload 都限制原因数量和具体字符串长度。

## 测试和验收

- 配置默认值、严格校验、config-editor snapshot 和 Swift draft/patch 往返；
- app、bundle、title、未知标题、`all` 连带、暂停、失败和诊断自保护的每屏原因映射；
- 多原因、优先级、`+N`、字符清理和具体值长度限制；
- 证明具体值不进入日志、capture JSON、FTS、timeline、memory、MCP 或模型输入；
- 浮层协议兼容、三种详细度、always/hover/click、鼠标穿透、点击命中、非激活、Space 和全屏；
- Unix Socket 权限、重连、generation 顺序、过期命令、非法 payload 和同用户限制；
- 诊断租约获取、确认、跨屏移动、释放顺序、daemon 重启、应用崩溃以及与现有暂停的组合；
- `separate`、`primary`、`all` 截图模式和活动窗口 AX gate；
- 多屏空白 InPrivate 实机验收，不使用真实隐私内容；
- 安装后 app/backend 所有权、helper 数量、源码/安装哈希、Python/Swift 测试、打包、签名和
  隐私日志扫描。

## 兼容性

现有配置自动得到批准的默认值。现有浮层样式和隐私规则保持工作。overlay 协议只新增可选
原因字段；字段缺失时按无原因处理。具体值不可用时，固定类别诊断仍可使用。
